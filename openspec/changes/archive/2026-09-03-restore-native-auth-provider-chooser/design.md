## Context

The Hermes Agent gateway supports RFC 8252 native app authorization (`/auth/native/authorize`), allowing desktop clients (Electron) to initiate authentication in the system browser using a PKCE pair and a loopback redirect URI (`http://127.0.0.1:<port>/callback`).

Currently, on gateways configured with both Nous Research Portal authentication and an enterprise/self-hosted OIDC provider, the desktop makes a request without an explicit `?provider=` parameter. Commit `ed5e17f4b8` accidentally stripped the multi-provider chooser dispatch while fixing issue #78906. Consequently, when `len(native_eligible) > 1`, `p` evaluates to `None` and an `HTTPException(404, detail="Unknown provider: ''")` is raised.

The rendering helper `render_native_provider_choice_html` is already present in `hermes_cli/dashboard_auth/login_page.py`. This design reinstates the connection between `routes.py` and `login_page.py`, ensuring multi-provider setups offer an interactive chooser to system browser users.

## Goals / Non-Goals

**Goals:**
- Present an accessible, brand-styled HTML provider chooser when `/auth/native/authorize` receives no `provider` query parameter and more than one native-eligible provider is registered.
- Thread all original desktop PKCE parameters (`code_challenge`, `code_challenge_method`, `redirect_uri`, `state`) into each provider option link so that clicking a provider seamlessly continues the PKCE authorization flow.
- Preserve existing single-provider auto-selection (auto-SSO convenience for standard single-provider deployments).
- Preserve existing password-only and password-fallback behavior introduced in commits `ed5e17f4b8` and `56f1afc834`.
- Reintroduce unit and route integration tests that verify multi-provider chooser rendering and query preservation.

**Non-Goals:**
- Changing desktop Electron client logic (`apps/desktop/electron/native-oauth-login.ts`). The desktop client is already page-agnostic and relies on the system browser to handle user interaction and eventually hit the loopback callback.
- Modifying session verification, cookie handling, or token exchange (`/auth/native/token`).
- Altering the styling or structure of `render_native_provider_choice_html` in `login_page.py`.

## Decisions

### 1. Re-import and Dispatch `render_native_provider_choice_html` in `auth_native_authorize`

- **Decision**: In `hermes_cli/dashboard_auth/routes.py`, import `render_native_provider_choice_html` from `login_page.py`. If `p is None and not provider`, inspect `native_eligible = [pp for pp in list_session_providers() if not getattr(pp, "supports_password", False)]`.
  - If `len(native_eligible) == 1`: select `p = native_eligible[0]` (existing auto-select).
  - If `len(native_eligible) > 1`: immediately return `HTMLResponse(render_native_provider_choice_html(...), headers={"Cache-Control": "no-store, no-cache, must-revalidate"})`.
  - If `not native_eligible`: fall back to selecting a lone password provider if `len(sess_providers) == 1`, preserving the existing password-provider handling.
- **Alternatives Considered**:
  - *Hardcoding provider priority (e.g., Nous over OIDC)*: Rejected. Different users or instances may prioritize self-hosted IdP over Nous or vice versa. The user must be given an explicit choice.
  - *Requiring Desktop to query `/api/auth/providers` and prompt natively in Electron*: Rejected. The RFC 8252 principle encourages keeping authentication interaction in the system browser so that webview exploits and credential sniffing are prevented.

### 2. Header and Cache Contract for the Chooser Page

- **Decision**: Return `Cache-Control: no-store, no-cache, must-revalidate` on the chooser HTML response.
- **Rationale**: The HTML links contain sensitive, single-use, or time-sensitive PKCE challenges and CSRF states generated by the desktop. Browser caching could result in stale `state` parameters during subsequent login attempts.

### 3. Test Harmonization

- **Decision**:
  - Re-add `NousStubAuthProvider` and `SelfHostedOidcStubAuthProvider` in `tests/hermes_cli/test_dashboard_auth_native_flow.py`.
  - Reintroduce `test_native_authorize_renders_multi_provider_chooser` verifying HTTP 200, header checks, provider button count, and link query parameter preservation.
  - Update `test_native_authorize_empty_provider_ambiguous_multiple_oauth_404` to assert the 200 chooser response instead of expecting 404.

## Risks / Trade-offs

- **[Risk] Multiple password providers registered alongside OAuth providers**  
  → **Mitigation**: `native_eligible` explicitly filters out `supports_password` providers. Password providers are handled by the separate password-login flow and do not pollute the OAuth chooser links.
- **[Risk] State parameter contains special or unencoded characters**  
  → **Mitigation**: `render_native_provider_choice_html` uses `urllib.parse.urlencode` and `html.escape` to ensure safe, valid query parameter encoding and HTML output.
